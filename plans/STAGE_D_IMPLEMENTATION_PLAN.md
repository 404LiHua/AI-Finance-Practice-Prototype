# 阶段 D 实施计划：稳健候选重建与新独立证据

计划日期：2026-07-24  
前置结论：阶段 C 工程完成，但推荐 v2 在独立 SCREENING 中因 MAE 差于 Naive 判定为 `FAIL`

## 1. 阶段 D 定位

阶段 D 不是对 C-4 的事后修补，而是建立新的研究周期。核心目标是提高跨时间区间的稳健性，并形成一套不依赖单一 validation 切分的新候选选择协议。

本阶段必须遵守以下边界：

- 封存 2023-06-09 至 2024-06-07 的 1,500 条 C-4 SCREENING 样本。
- 不读取其逐样本预测、逐股票排名或误差分组来设计新模型。
- 只允许引用公开的阶段结论：推荐 v2 没有击败 Naive，复杂结构的开发期优势未能稳定外推。
- 新候选不得在 C-4 区间重新评估并声称独立性。
- 新的未来数据只有在 D 阶段候选、基线和规则冻结并获得明确授权后才能获取。

## 2. 研究假设

阶段 D 优先验证以下与 C-4 汇总结论直接相关、但不依赖其逐样本信息的假设：

1. 单一时间切分导致模型选择方差过大，滚动起点验证更适合金融周序列。
2. 收益预测需要显式收缩到 Naive，并根据开发期滚动验证确定固定收缩强度。
3. 绝对收益误差与方向判断应分开建模，避免方向能力被幅度误差抵消。
4. 模型容量和图结构应继续受限，优先研究确定性结构，不恢复随机 Gumbel 搜索。
5. 相比继续增加复杂模块，跨折稳定性、校准和相对 Naive 增益更应成为主要选择依据。

## 3. 数据协议

### D-0.1 开发数据

- 只使用日期不晚于 2023-06-02 的现有数据。
- 将该区间重新定义为阶段 D 的选择暴露开发集，不再保留其中任何部分作为最终证据。
- 采用至少 3 个按时间前推的 rolling-origin 折，每折只使用过去数据拟合，使用后续连续区间验证。
- 每个候选必须在完全相同的股票、日期和缺失处理规则下评估。

### D-0.2 封存数据

- C-4 区间继续保持只读封存，不进入特征、训练、早停、校准、模型选择或阈值制定。
- 在计划和代码中增加路径拒绝检查，防止误读 C-4 数据目录。

### D-0.3 新独立区间

- 暂定预留 2024-06-14 至 2025-06-13 作为未来 D-SCREENING 候选区间。
- 当前只登记日期，不获取、不读取、不统计行数。
- 若数据覆盖不足，在冻结前只允许整体平移区间，不能先查看模型结果。

## 4. 工作包

### D-1：滚动验证与数据封存框架

预计工作量：1–2 天。

- 实现 rolling-origin split 生成器和折间一致性检查。
- 增加 C-4 路径拒绝、日期上限和数据哈希审计。
- 统一输出每折、每种子、逐股票和总体指标。

验收标准：至少 3 个严格时间顺序折，无未来信息泄漏；C-4 数据路径读取测试必须失败。

### D-2：受限稳健基线

预计工作量：2–3 天。

候选范围预先限定为：

- Naive。
- FreTS return-only L4。
- 价格版 Minimalist Transformer L8。
- 仅时域 Transformer。
- 固定时间图控制。
- 固定收缩预测：`α × 模型预测 + (1-α) × 0`，α 仅允许从预登记小网格中选择。
- 幅度/方向双头的轻量时域模型，禁止动态图和随机采样。

验收标准：所有模型使用相同折和统一评估器；不新增未经登记的候选族。

### D-3：跨折选择与诊断

预计工作量：2 天。

主要选择指标：

1. 相对 Naive 的跨折平均 MAE 改善。
2. 最差折 MAE 相对 Naive 的保护。
3. 跨折 RMSE、方向 F1 和种子变异系数。
4. 高绝对收益组误差比例和最差五股票误差占比。

建议候选准入条件：平均 MAE 至少在 2/3 折优于 Naive，且最差折不比 Naive 高 2%；具体门槛必须在 D-4 冻结时最终确定。

### D-4：新候选冻结

预计工作量：1 天。

- 唯一锁定一个候选结构和固定推理方式。
- 冻结基线、折定义、种子、指标、门槛和失败条件。
- 生成新的 SHA-256 清单和独立加载复算记录。
- 冻结后禁止修改候选或根据未来结果挑选折、种子和收缩权重。

### D-5：新独立 SCREENING

预计工作量：等待授权后 1 天。

- 候选和规则冻结完成后，单独请求用户授权。
- 一次性获取预留未来区间并运行候选与冻结基线。
- 只允许 `PASS`、`FAIL`、`INCONCLUSIVE` 或完整性失败。
- 运行后不在同一数据上修补。

### D-6：阶段收尾

预计工作量：1 天。

- 更新最终报告、版本、标签、GitHub 和 `importance` 归档。
- 明确区分开发期证据和独立证据。
